# Drafts

A draft keeps an automation, application, value, fix, or reference that isn't
finished yet, so you can come back to it later. A draft never runs, and
AppyTappy doesn't read it until you finish it and save it.

## Save a draft

While you make or change something, select **Save as draft**. Its **?** says
what a draft keeps. Until it can be saved, the editor lists what it still
needs, such as `Name the value.` or `Add an action.`

If you select another page while something isn't saved, AppyTappy asks
whether to leave, and says what you would lose and what a draft would keep.
Select **Save as draft** there to keep your work, **Leave** to lose it, or
**Stay** to go back to it.

When you opened one thing from another, such as a new value from an
automation, **Save as draft** on the value keeps the value and returns to the
automation, as you left it. If you select another page instead, **Save as
draft** in the question keeps each of them as its own draft: the value on the
**Values** page and the automation on the **Automations** page. The two are
no longer tied together. You finish the value first, then finish the
automation and pick the value in it.

## What a draft keeps

- **An automation** keeps everything in its editor: its name, the application
  and the value it watches, the comparison, each action with how and where it
  clicks, whether it undoes its actions, and the wait before it can run again.
  It keeps the pictures its clicks look for.
- **An application** keeps its name, how its window is found, and how often
  the window changes size.
- **A value, fix, or reference** keeps its screenshots, each the whole
  window, and what you set up on them: the region, **Stays at**,
  **This content may move**, the check with its colors, states, and
  tolerances, the reference it reads with, the labels, the characters a
  reference needs, and the text you added with **Find more like it**.
  Screenshots that **Record screenshots** kept are kept like the ones you
  took.

A draft doesn't keep these, so finish them before you save it:

- A [recording of readings](References.md#record-readings) that runs or
  waits for you to look through it, and the readings you kept from one.
  Select **Save reference** to keep those.
- A [recording of screenshots](Values.md#record-screenshots) that still runs.
  Stop it first; the screenshots it kept stay.
- A **Find more like it** list you haven't added from yet.

An [edit of a saved value](Values.md#edit-a-value) can't be saved as a draft.
It changes a value your automations already use, so you either select
**Save changes** or drop it, and the question before leaving says so. A
[fix](Values.md#fix-a-value-at-one-size) can.

A draft's screenshots stay on this computer, in the draft, until you finish
or delete it ([What AppyTappy keeps](Getting-started.md#what-appytappy-keeps)).

## Finish or delete a draft

Drafts show on the page that lists what they make, with a **Draft** mark and
what each still needs. An automation or application draft shows under the
saved ones. A value, fix, or reference draft shows under its application. A
value can have several fix drafts. AppyTappy doesn't match them to window
sizes: **Fix at this size** always starts a new fix, and you finish a fix
draft from its own row.

- **Finish** opens it where you left off. A value, fix, or reference draft
  first asks for its application's window again, then brings back its
  screenshots. Save it as usual and the draft goes away. If you select
  **Change window** there, AppyTappy asks first and starts over on the new
  window; the draft stays as it is unless you save it again.
- **Delete**, then **Delete draft** to confirm, removes it with its
  screenshots and pictures. While you finish a draft, **Delete draft** there
  removes it too, without saving.

A saved item that has a draft of changes shows **Draft changes**, and
**Finish draft** in place of **Edit**, so you carry on from the draft. To edit
it as saved instead, finish the draft and select **Delete draft**; the saved
item stays as it was. For the same reason, a new value can pick a reference
that has a draft of changes but can't edit it or record readings for it
there, and when you choose an application for a value or a reference,
**Finish draft** takes the place of **Change how it's found** for an
application that has a draft of changes.

Removing an application deletes its drafts with it: those of its values,
fixes, and references, and its own draft of changes. Deleting a value deletes
its fix drafts. The question before either says so.

A draft whose application can't be read says so and can only be deleted. So
can a fix draft whose value was changed since, such as to another check, and
a draft saved by another version of AppyTappy Setup. A draft whose file can't
be read at all shows under the automations on the **Automations** page, and
can only be deleted too. Until you delete it, AppyTappy keeps every picture
that clicks look for, because it can't tell which of them that draft uses. If
a draft's screenshot can't be read when you finish it, AppyTappy says so where
you chose the window: select **Cancel**, then delete the draft on its page. A
screenshot of a window larger than AppyTappy reads isn't kept with its draft,
and the draft's row says to make the window smaller and take it again.
